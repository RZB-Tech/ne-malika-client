# ИИ-компаньон neMalika

Помощник работает на покупательских страницах: автоматически открывается при первом посещении в этом браузере, затем вызывается кнопкой. На телефоне кнопка находится выше нижней навигации и панели сравнения. В кабинетах продавца и администратора помощник не показывается.

Поддерживаются русский и узбекский (латиница и кириллица). Язык ответа следует языку сайта. На странице товара помощник получает ID открытого товара, чтобы отвечать о нём по актуальным публичным данным.

## Запуск

Backend: `D:\Sources\work\ne-malika-server`.

Используется существующий серверный `OPENROUTER_API_KEY`. Модель по умолчанию — `openai/gpt-4o-mini`; её можно переопределить через `OPENROUTER_ASSISTANT_MODEL`. Ключ не нужен в клиентском окружении. После изменения backend его нужно пересобрать и перезапустить.

Клиент обращается к `POST /api/v1/assistant/chat` через существующий `NEXT_PUBLIC_API_URL`. При локальной разработке без этой переменной используется `http://localhost:3001`; frontend и backend должны быть запущены, а origin клиента — разрешён в CORS backend.

Пример тела запроса:

```json
{
  "messages": [{ "role": "user", "content": "Нужен ноутбук для учёбы до 5 млн сум" }],
  "productIds": []
}
```

Ответ: `message`, `suggestions`, `products`, `links`. Бесплатный для покупателя маршрут доступен без входа, ограничен 8 запросами в минуту на IP. Все ответы на сообщения пользователя, включая приветствия и благодарности, формирует модель. Каждый ответ требует двух ограниченных по времени обращений к OpenRouter: определение необходимости и параметров поиска, затем формирование ответа. Готовых ответов и списков фраз для их подстановки на backend нет.

## Данные и поведение

- Категории и рекомендации берутся из backend. Бюджет в сумах, категория и состояние фильтруются в SQL до ограничения выборки; скрытые товары и неактивные магазины исключаются общими правилами каталога.
- Модель получает ограниченную выборку из 12 предложений. Это не гарантия самой низкой цены на всём сайте. ID рекомендаций проверяются по результатам поиска; навигационные ссылки разрешены только на известные разделы сайта.
- Помощник задаёт уточняющие вопросы, объясняет выбор техники и функции сайта. Покупку, оплату и отправку сообщений продавцам он не выполняет.
- Ответ относится к последнему сообщению пользователя; история и открытый товар служат контекстом. «Привет» после подбора ноутбука вызывает приветствие, а «Привет, нужен ноутбук до 5 млн сум» продолжает обычный подбор. Поиск, который не выполнялся, явно отделён от поиска без результатов.
- Вступительный текст при открытии пустого чата локальный и не вызывает модель. Ответы на отправленные сообщения приходят из OpenRouter. Если он не настроен или не отвечает, интерфейс показывает ошибку и позволяет повторить сообщение.
- Последние 6 пар сообщений сохраняются в `sessionStorage` отдельно для каждого языка, максимум на 24 часа и на время вкладки. Закрытие панели не прерывает текущий запрос. «Начать новый диалог» очищает переписку и отменяет запрос.
- Автоматическое открытие запоминается в `localStorage` под ключом `nemalika:assistant:seen:v1`. Для повторной проверки первого посещения используйте чистый профиль браузера или удалите этот ключ.
- На backend переписка не сохраняется и не выводится в журнал ошибок; история и публичные сведения каталога передаются OpenRouter для ответа.

## Проверки

В backend: `pnpm test` и `pnpm build`. Тесты `src/modules/assistant/assistant.spec.ts` проверяют DTO, историю, модель, бюджет, пустой поиск, локализацию, SQL-фильтры и отбрасывание выдуманных ID/ссылок.

В клиенте: `pnpm exec tsc --noEmit`, lint изменённых файлов и `pnpm build`. В браузере проверяются первое/повторное посещение, сворачивание, мобильная панель, ввод, состояния ошибки и переключение языка.
